1. 原子性构建 & 发布：一次构建生成的 dist 包，需同时包含 “注入版本号的前端代码” 和 “待上传的 sourcemap 文件”，上传 sourcemap 和发布前端包必须使用同一个构建产物，禁止多次构建；
2. CI/CD 固化流程：在 Jenkins/GitHub Actions 中，将 “生成版本号 → 构建项目 → 上传 sourcemap → 发布前端包” 做成一个不可拆分的流水线，避免人工干预；
3. 发布后验证：发布完成后，随机打开线上网页，检查控制台输出的版本号，是否和 COS 中 sourcemap 目录的版本号一致；
4. 禁止手动修改：禁止手动修改 dist 包中的版本信息（如 version.json、HTML meta 标签），否则会导致版本匹配失效。
